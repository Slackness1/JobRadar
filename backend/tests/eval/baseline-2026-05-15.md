## 真发现 1 · followup 反问环节 SUT bug 🐛

`05_chenrui_reverse_question` fixture: 候选人在第 6 题（反问环节）问"中频组最近有没有重大策略框架重构"。SUT 回了：

> 你问中频组策略重构，是担心现有策略失效还是想接触更多数据源？以前实习有经历过框架大幅转向吗？

Judge 抓得准（命中 `expected_followup_targets_must_avoid` 的"反问候选人为什么问这个问题"），给 0 分。

**修法**：`backend/app/services/interview/adaptive.py` 在 `should_follow_up` 决策前加 short-circuit — 如果当前 main 是 skeleton 第 6 题（反问），强制 advance / 收尾，不 follow-up。已加入 `TASKS.md` 高优先级。

## Eval 框架 limitation 1 · judge 没看 SUT 自己承认的 tier_label

8 个 track_relevance 0 分案例，**全部** SUT 自己也标了 `tier='有差距'` + `final_score=12-30`。比如:
- `02 商科普通本 × 04 PE`: SUT 推 "券商支持/财富管理" + tier="有差距" + final=12
- `04 量化硕 × 01 公募研究`: SUT 推 "基本面研究" + tier="有差距" + final=28

SUT 内部知道这是 gap，但当前 judge prompt 只看"推荐轨道是否命中 gap_tracks"，没看 `tier_label` 是不是认错了。

**Phase 2 calibration**:
- judge 改成 "命中 gap_tracks **且** tier='强匹配'" 才判 0
- "命中 gap_tracks **且** tier='有差距'" 判 1-2 分（承认了 gap）
- "命中 strong_match_tracks **且** tier='强匹配'" 判 3 分

需要重新跑 baseline。

## Eval 框架 limitation 2 · 强制 1:1 推荐没法表达"不该推"

当前 runner 让 SUT 对每个 (student, jd) pair 强制出一个 recommendation 项 — production 里 recommendation 管道会用 `final_score` 过滤掉低分。Eval 应该:

- 在 judge prompt 里允许"SUT 推 final_score < 30 + tier='有差距' = production 里会过滤掉"理解为合理
- 或者让 SUT 接口支持显式 "abstain" 输出

Phase 2 一并改。

## 一些 SUT intermittent bug

- `04 量化硕 × 02 中信研究` track_relevance 阶段 SUT 返回空 JSON (`Expecting value: line 1 column 1`)。retry 已经做了，但 retry 仍空。可能是 DeepSeek 偶发对某些 prompt 拒绝。
- `01 张诺 × 05 量化研究`、`02 商科普通本 × 05 量化研究`: SUT 返回 valid JSON 但 `matched_track_label` 是 null。说明 SUT 自己认为"无法推荐"，但没用 abstain 接口。

3 个 intermittent edge case 不阻塞 baseline，已在 runner 里 skipped 处理（`_is_invalid_recommendation`）。

## 其它已知约束

- **MiMo Token Plan 警告**: 控制台明示"套餐仅在编程工具中使用，否则可能会导致订阅被暂停或 API Key 被封禁"。我们用 MiMo 当 eval judge 算 dev/test 工具用途，**理论上**算编程工具圈，但严格说不是 IDE 内的编程辅助。如果用量大被封了，需要换 pay-per-token 或 fallback 到 deepseek-v4-pro 当 judge（接受同厂商 bias 风险）。
- **判分单运行不稳**: judge 是 stochastic LLM，单次跑分有 ±1 噪声。pytest test_touyan_v1.py 的回归断言用了 1 分 tolerance，本次 baseline 还需要至少 2 次重跑确认稳定性。

## 下一步建议

## Addendum · 2026-05-16 · followup hard rule 修复 + interest_decider

baseline 跑出"反问环节 SUT bug" (case 05 = 0 分) 之后,落了 hybrid 修复:

**Hard rule** (机械,无 LLM,毫秒级):
- 反问环节(skeleton 最后一题已答) → 强制 advance,返回礼貌收尾文案
- followups_under_current ≥ 3 → advance (cap 从写死 2 提到可配置 3)
- 答案 < 80 字 → advance (太短没东西可问)

**Soft rule** (`app/services/interview/interest_decider.py`,LLM 一次调):
通过 hard rule 之后才跑。让 LLM 像真实面试官一样判断"还想继续追问吗",4 个判断维度:
  1. 业务强相关吗 (跟 JD 业务方向 / 团队最近做的事是否对得上)
  2. 候选人埋了钩子吗 ("我还做过 X 但没展开" / 提了新 entity 没深入)
  3. 答案有可 follow-up 的具体细节吗 (公司/数字/项目/决策点)
  4. **不**被分数 / 完整度这种系统指标干扰

替代旧的"`prev_score.overall < 60` 或 `misses ≥ 1`" 系统视角逻辑 — 真实面试官关心的是
**业务相关性 + 候选人引导力**,不是答案是否完整。

### 已知 limitation (留 TASKS.md backlog)

- **interest_decider 没被 eval 测**: eval runner 的 `sut_generate_followup` 是 standalone prompt,不走 orchestrator,所以 interest_decider 只在 production runtime 真跑。要测它需要 Phase 1.5 的 multi-turn simulator 接进来。
- **track_relevance 1.21 仍偏低**: 11/24 是 0 分,核心是 judge prompt 没看 SUT 自己承认的 `tier_label`(已在 backlog: "Calibrate judge prompt — 看 SUT 的 tier_label")。这是 eval 框架问题,不是 SUT bug。

## Addendum 2 · 2026-05-16 · judge calibration + multi_turn 接入

接连落两件事:

### (a) Judge calibration — 让 judge 看 SUT 自己的 tier_label

`judge_track_relevance` prompt 重写,加了 SUT 自洽性维度:

```
SUT 推 gap track + 自己说"有差距" → 1 分(合理识别,production 会过滤掉低分)
SUT 推 gap track + 自信说"强匹配" → 0 分(真 bug)
SUT 推 strong_match + 说"强匹配"  → 3 分
SUT 推 strong_match + 谦虚说"可迁移" → 2 分(低估)
```

效果对比:

| 阶段 | mean | hist (0/1/2/3) | 关键变化 |
|---|---|---|---|
| 旧 (no calibration) | 1.21 | 11/2/6/5 | 11 个 0 分 — 多数是 SUT 自己承认 gap 但 judge 没看 |
| 新 (calibrated) | **1.29** | **3/13/6/2** | 0 分降到 3 个(真 bug),1 分从 2 升到 13(合理处理) |

mean 没大涨 (1.21→1.29),但 distribution 翻了 — 旧的"不当一回事的极端打分"变成"系统性归因到 SUT 自洽性"。

**新发现**: 0 个 3 分 → SUT 在所有 case 里**从不给 tier='强匹配'**,即使候选人简历完美对口。SUT prompt 训得太保守,加 backlog。

### (b) Multi-turn simulator 接入 — interest_decider 终于被 eval 测到

新模块 `tests/eval/multi_turn.py` + 新 metric `multi_turn_quality`:

- 跑完整模拟面试 (~6 skel × 0-3 follow-up each)
- SUT 出题,simulator 演候选人答,interest_decider 判 continue/advance,judge 评每个 follow-up
- 反问环节 hard rule 收尾

**2 个 fixture 跑完**:

| Combo | total turn | follow-up | avg score |
|---|---|---|---|
| 01 张诺 × 公募基金 | 19 | 12 | 2.00 |
| 04 王哲 × 量化研究 | 19 | 12 | 2.33 |

**亮点 — interest_decider 完全按真实面试官业务感工作**。Advance 推理示例:
- "项目属于期权做市/衍生品定价,与 JD 要求的 Alpha 因子研发方向直接关联度有限"
- "候选人讲的光伏行业项目与 JD 要求的大消费板块缺乏直接业务关联"
- 不被 score / 完整度干扰,看**业务对齐**

**真发现 (multi_turn 暴露的 SUT 偶发 bug)**:
1. SUT follow-up 偶发跳到候选人简历另一段经历 (24 turn 里 1 次)
2. SUT 偶发 hallucinate 候选人没说过的 entity ("CPI 公布日检测")
3. judge 对 transferability 测试偏严: SUT 问"动态利用率思路能否搬到消费行业" 是合理面试技巧,judge 判 0 因为"跳了项目"。multi_turn judge prompt 可再 calibrate。
4. _parse_score 偶发解析失败 (LLM reasoning 里用了 unescaped `"`)

3 个 issue 都加 TASKS.md backlog。
