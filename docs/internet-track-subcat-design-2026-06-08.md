# 设计:互联网独立赛道 sub_cat + enrich 进池(SAIF 2026 秋招)

> 日期 2026-06-08。出单:岗位爬取线。状态:**待用户 review spec**。
> 目标:把已入库的 ~1.2 万互联网大厂活岗,经"打标 + 进池"接入推荐,作为**与金融并列的独立互联网赛道**。
> 配套:实施文档 `impl-tata-internet-bigtech-2026-06-08.md`(爬取/覆盖)、发现清单 `jobradar-sync/internet-taxonomy-final.md`。

## 1. 目标与非目标

- **目标**:让互联网大厂的 **AI 类 + 高薪非技术类**岗位被正确打标(sub_category)、进推荐池,SAIF 学生(尤其想去 AI 产品/AI 应用开发/产品/管培的)能搜到/被推到。
- **用途**:**打标 + 推荐检索**。**非目标**:本轮不做这些赛道的面试 rubric / 知识深度(那需另爬牛客/小红书语料,留作后续阶段)。
- **独立赛道**:互联网 sub_cat 自成一组(`industry_focus=互联网`),不混入金融池;推荐 recall 按 sub_category 匹配学生偏好,天然隔离(金融学生匹配不到互联网 sub_cat,反之亦然)。
- **数据驱动**:赛道由 1.2 万真实 JD 聚类(KMeans 70 簇)+ GPT-5.5 归并而来,非拍脑袋。薪酬数据我们没有,"高质量"靠**角色类型**判定(产品/AI/算法/研发/管培=进池;骑手/客服/门店/地推/基础职能=不进池),同金融 taxonomy 的"机构销售 vs 零售"思路。

## 3. 管道改动(三道闸都要为互联网赛道开通路)

现有三道闸全金融调校,直接跑会把互联网岗全挡。改动:

### 3.1 quality 闸
互联网高质量岗(产品/AI/研发/数据/管培…)不能被金融版 v3 误降 low/support。方案:**新增互联网 quality 判定路径**(或在 enrich 候选阶段对互联网赛道岗跳过金融 quality、直接用赛道 tier 给 good/internship_only)。低质量角色(骑手/客服/门店/职能HR)仍打 support/low → 不进池。

### 3.2 sub_cat 闸 + GT 横向解闸(核心改动)
`12_enrich_sub_cat.py` 现候选 = `quality good/intern AND company IN 119金融GT`。改:
- **候选扩展**:把 32 大厂(及后续 tata 互联网源)纳入候选,**绕过金融 GT 过滤**(对互联网赛道岗不卡 GT);
- **分类目标**:Pass1 判 strategy_type ∈ {`AI 应用_PM_开发`, `互联网`};Pass2 判具体 sub_cat(§2 的 19 桶);
- **写入**:`sub_category` + `strategy_type` + `industry_focus="互联网"`(AI 桶可叠加 "AI应用层");
- 判到不进池桶 / 低质量角色 → 不写 sub_category(=不进池),不污染池子。

### 3.3 独立赛道呈现
recall 按 `sub_category` 匹配学生偏好赛道,天然隔离。新增的互联网 sub_cat 用 `industry_focus=互联网` 作为**赛道选择器分组**,前端把"互联网"作为与金融并列的一个可选赛道大类。`institution_tier` 对互联网可置"大厂/独角兽"或留空(非金融分层,后续再细化)。

## 5. 执行顺序(用户额度足,LLM 走 GPT-5.5 xhyapi 渠道 / 或 DeepSeek)

1. **AI 7 桶先行**(已有桶,不等非AI):对 12k 大厂岗跑 enrich,先把 AI 岗进池(最急)。
2. 非 AI 12 桶 taxonomy 落地 + enrich。
3. 全量验证:抽样核对 sub_cat 准确率、池子互联网含量、与金融池隔离。
4. dev 跑完进生产走 `jobradar-vps-deploy`。

## 6. 测试 / 验收

- enrich 后抽 20-30 个互联网岗肉眼核对 sub_cat 对不对、tier 判对没(骑手/HR 没混进池)。
- 金融池不受影响(金融岗 sub_cat / 推荐结果回归不变)。
- "互联网"赛道可在前端作为独立大类选择;选金融的学生推荐结果里不混互联网岗。
- 产品经理 vs 产品运营拆分核对(3921 实际分布)。

## 7. 风险 / 待定

- **"互联网产品经理"3921 偏大**:GPT 归并的估值,真实分布到 enrich 分类才定;可能 产品经理 << 3921,大头落产品运营/研发。验收时核。
- **quality 改动别波及金融**:互联网 quality 路径要与金融 v3 隔离,避免回归金融岗判定。
- **institution_tier 对互联网无现成分层**:本轮可留空或粗分(大厂/独角兽),不阻塞打标推荐。
- **官网申请链接缺失**(click 限流):互联网岗暂无直达链接,学生申请走公司官网;不阻塞进池。
- **后续阶段**(非本 spec):牛客/小红书语料 → 真实薪酬/口碑 tier 校准 + 互联网赛道面试 rubric 深度。
