# Reviewer 4 — 链路一致性 (AI 产品 reviewer 视角)

> 评的是: **chat 阶段学生说过的事 → 面试出题 + 评分有没有"用上"** —— 即 JobRadar 作为"带记忆的 conversational agent",是不是真的"懂"林婉清这个学生。
>
> Reviewer 角色: SaaS PM + AI Product Architect (4y conversational-agent w/ memory)。
> 输入: persona ground truth + Phase 2 chat log (7 turn) + memory snapshot (13 条) + Phase 3 transcript (22 turn, 21 答题, 6 skeleton + 15 follow-up)。

---

## 总评

- **总分**: **6.4 / 10**
- **一句话定调**: 系统"懂"这个学生的程度 = **它知道学生的核心 entity 名字,也敢追问到她的痛处(德方纳米 DCF / Walk-forward / 海天调研),但它对学生在 chat 里主动暴露的两条最关键的自我修正信号 —— 招商基金其实是固收+ / 海天报告只写了 1500 字 —— 完全没拿来在面试里交叉验证,导致面试里出现了多处"学生 chat 里都纠正过了,面试还在按简历原版往下问"的链路裂缝。

> 它是一个能"听得见"学生 chat,但**忘得太快、用得不深**的产品。Memory 写进去了 13 条,真正在面试场景被"用上"的是大概 5 条;其余 8 条沦为快照里的装饰。

## "系统懂学生"的高光时刻

### 1. **Turn 1 德方纳米 WACC 追问** — chat → 出题最干净的命中
学生 chat turn 5 主动说: *"德方纳米 DCF 内在价值高 35%,mentor 一句 'WACC 怎么算的,锂电中游 beta 你拍脑袋了吧' 让我哑口无言。"*
面试 turn 1 出题: *"你提到对德方纳米做过深度跟踪,那跟踪过程中你有没有给出具体的目标价或买卖建议?团队当时有没有采用你的观点?如果没有,你后来反思问题出在哪?"*
**评**: 这是系统真"记住"了 — `experience#14` 直接驱动了 follow-up 链 turn 1-3,3 层连续追到 2027 毛利率假设。学生在 chat 里埋的"痛处",系统精准把它做成了入口。

### 2. **Turn 5 walk-forward 追问** — chat → 出题 + 反馈双命中
学生 chat turn 7 主动说: *"样本外 MAE 6.8%,比线性基准低 11.2%,拿了课程优秀奖,但其实没有做严格的 walk-forward 验证,这块有点弱。"*
面试 turn 5 出题: *"你提到 MAE 6.8% 没有做信号到持仓的回测,导师说不能直接拿去用 —— 如果现在时间和资源有限,你会优先解决 walk-forward 验证,还是先做信号到持仓的回测?"*
**评**: 系统把学生自己暴露的两个弱点(walk-forward 没做 / 信号到持仓没做)做成了二选一的逼问,迫使学生说出 prioritization 思路。这是 memory→ 出题最 elegant 的设计。

### 3. **Turn 8 海天调研连接** — 跨 turn 间接复用
学生 chat turn 2-3 说: *"海天那篇深度报告里真正自己写的是渠道库存敏感性那一节,大概 1500 字。"*
面试 turn 8 出题(skeleton 关键取舍): 学生主动选择讲调味品渠道库存跟踪 → 系统在 turn 9 follow-up: *"那次汇报出错后,你和师兄具体做了什么调整来修正混合路径?"*
**评**: skeleton 题没直接命名"海天",但学生自然就讲了 — 这反向说明 memory snapshot 里 `experience#10`(维护跟踪模型周会引用)对学生的语义引导起作用了。出题没强提示,学生主动回到了 chat 里说过的剧本。

### 4. **Turn 18 招商基金固收+ 反向引用** — 学生主动联系,系统在评分里 capture
学生 turn 18 答题主动说: *"招商基金那段固收+ 的经验里,他们对债券部分有非常明确的入场和退出条件,权益这块我没有接触到类似的机制。"*
score.hits 里出现 `"联用实习经历"` —— 这是 15 个 follow-up 里第一次评分系统真正接受了"招商基金 = 固收+" 这个 chat 阶段的修正,而不是按简历原版的"权益投资部"。
**评**: 算半个高光 — 系统终于"听见"了 chat turn 4 的修正。

### 5. **Turn 16 嘉实选岗题 + Turn 20 反问** — 偏好闭环
chat turn 1 学生说想申"嘉实股票行业分析师";memory `preference#9` 记下来。面试 skeleton turn 16 *"为什么选这家公司"* 把嘉实摆在题面,turn 20 反问题也定向嘉实文化。
**评**: 这一条不算 entity 命中,但说明 `preference` category 的 memory 至少串起了首尾两个 skeleton。

## "系统忘了学生"的低谷时刻

### 1. **chat turn 4 学生主动纠正"招商基金不是权益投资部,是混合资产投资部 / 固收+ 组"** —— 面试 turn 7 系统又把它当成了"可转债增强量化工具"专家在问
面试 turn 7 *"你提到在招商基金接触了可转债增强的量化工具,那边具体的信号触发和基金经理使用流程是怎样的?有没有因为信号不准导致回撤的案例?"*
学生 chat 阶段已经说过 *"我没有真正进入决策""mentor 给现成代码,我跑了下参数"*,这条信息 memory snapshot 没有抓 — 因此面试官等于在问"你深度参与过的可转债策略,信号触发流程怎么走"。学生只能再说一遍"我没参与决策"。turn 7 score 给 55,misses 写"缺业务痛点 / 行业认知浅" —— 这其实是**系统问错了人**,但反过来扣学生分。
**评**: 这是最典型的"memory 漏抓 → 出题踩雷 → 评分还冤枉学生"三连击。

### 2. **chat turn 3 学生说海天报告"真正自己写的只有 1500 字渠道库存敏感性"** —— 面试 turn 0 自我介绍后没有任何一题去 probe 这个"虚标 vs 实写"
persona 的 anticipated_grey_areas 明确点出: *"她说'参与撰写 3 篇深度报告',追问'你具体写了哪几节、字数多少、署名顺序'会露馅,实际只写过 1500 字。"*
chat memory 里其实没显式 capture "1500 字"这个数字,但 `experience#10` 是有维护模型这条 evidence 的。面试出题完全绕开了"深度报告署名 / 字数"这个学生自己主动暴露过的 gray area。系统没有"用上"学生 chat 里的诚实自白来做反向追问。
**评**: 这是 Reviewer 视角下最遗憾的盲区 —— 学生主动给了"破口",产品没接住。

### 3. **chat turn 6 学生提到上财金融硕士 + 中南财经政法本科 + 推免** —— 面试 22 个 turn 一次都没用过
memory snapshot 有 `identity_fact#8 / #16`(上财金融硕士),也有 `evidence` 类条目。但是出题里没有一处"你本科到硕士的研究方向跨度怎么衔接""推免到上财投资学方向,你的导师方向跟买方行研有什么呼应"这种顺手就能问的题。学校背景信息**完全沉睡**。
**评**: identity_fact 类 memory 写了等于没写。

### 4. **chat turn 6 学生说"Python + Tushare + Wind 都用得比较熟练"** —— 面试评分里 0 处引用 "Tushare"
skill_claim#18 记得清清楚楚。面试 turn 12 学生自己主动讲了 "Python + Tushare 抓 6 家公司分季度财务面板"。系统接住了出 follow-up turn 13,但 hits/misses 里没有一处提到 Tushare 这个具体工具。后续 17 个 turn 也再没出现过 Tushare 这个关键词。
**评**: skill_claim 这一类 memory 在评分维度上是"哑火"的 — 它不被评分系统作为可对照的 baseline。

### 5. **Turn 13 学生自己说"系统把中信建投面板和硕士 XGBoost 混在一起问了,这两个是独立的"** —— 这是**学生在面试里被迫修复系统的 memory 错乱**
面试 turn 13 出题: *"你手动补录东鹏饮料那几季度的数据后,这个数据集用于景气度预测时,相比于空着 N/A 的方案,模型准确率有量化的改进吗?"*
学生答: *"对对对,我说一下,这里有一个时间上的错位 —— 中信建投的那个分季度财务面板和后来硕士课程的景气度预测是两个独立的东西,不是前后延续的。"*
这道题的前提是错的 —— 系统把 `experience#10`(中信建投 Tushare 面板) 和 `experience#19`(硕士 XGBoost 模型) 当成同一个 pipeline 来追问。**学生在面试里反过来教育系统**。turn 13 score 还给了 45 分,misses 里写"未回应该题核心" — 题本身的前提不成立,学生纠错却被扣分。
**评**: 这是 chain consistency 最严重的 bug 类型 —— 不是单条 memory 没用,是**两条 memory 被错误地"语义粘连"** 在一起。AI agent 跑 4 年了我看到过的最不能容忍的 memory failure 模式。

## chat → 面试 entity 引用率统计表

> 引用 = 出现在 question 文本中(出题) / hits / misses / bonuses 文本中(反馈)。entity 别名也算(如"中信建投" = "卖方研究消费组")。

| chat 里说过的关键 entity | 出现在面试出题里 | 出现在面试反馈里 |
|---|---|---|
| 中信建投消费组 / 卖方 | 3 次 (turn 7/9/11 间接) | 1 次 ("未联用具体经历" turn 9) |
| 招商基金固收+ / 混合资产 | 1 次 (turn 7 错问成"可转债深度参与") | **8 次** ("未联用招商基金经历" turn 2/3/5/7/11/14/17 + bonuses turn 18) |
| 海天调研 / 渠道库存 | 2 次 (turn 9/10 follow-up 走调味品取舍) | 2 次 (turn 8 / turn 18 隐含) |
| 德方纳米 DCF | 3 次 (turn 1/2/3 follow-up 链) | 3 次 (hits "WACC假设""核心假设虚") |
| XGBoost MAE 6.8% / 47 特征 | 3 次 (turn 5/6/13 follow-up) | 2 次 (hits "深挖特殊bias""量化结果") |
| 容百科技 | 0 次 | 0 次 |
| Tushare | 0 次 (学生自己 turn 12 提到) | 0 次 |
| CFA Level II | 0 次 | 0 次 |
| 上财金融硕士 / 投资学方向 | 0 次 | 0 次 |
| 中南财经政法本科 | 0 次 | 0 次 |
| 京东淘宝爬虫 | 1 次 (隐含 turn 8 调味品取舍) | 0 次 |
| 课程优秀奖 (2/24) | 0 次 | 0 次 |

**引用率汇总**:
- 出题: **6 / 12** entity 被用上(50%),其中德方纳米 + XGBoost + 海天调研 3 条形成了真正的 follow-up 链
- 反馈: **5 / 12** entity 被用上(42%),且**招商基金被 misses 引用 8 次 是负向数据 —— 系统反复批评学生"未联用招商基金经历",但自己的出题没有给学生联用招商基金的入口**
- 完全沉睡的 7 条: 容百科技 / Tushare / CFA-2 / 上财 / 中南财大 / 京东淘宝爬虫直接命名 / 课程优秀奖
- chat 阶段主动诚实自白的 2 条关键 gray-area (海天 1500 字 / 招商基金固收+ 性质) 在出题侧**没被设计成 probing 题**,只在评分侧被当成"未联用"指标使用

## 跟 SAIF 老师说的话

老师,我做 conversational agent 的产品 4 年,直白告诉您看完这条链的判断:JobRadar 是**真的有 memory 在 drive 出题** 的,这不是 demo。德方纳米 → WACC → 2027 毛利率假设 → 产能出清时间线,这条 3 层 follow-up 链在没有 memory 的 ChatGPT 套壳产品里**绝对做不出来**,因为它需要系统精确知道"林婉清主动跟我说过 mentor 用 WACC 怼了她"。这一处把我说服了。

但**它现在的 memory pipeline 有两类硬伤** —— 第一,**identity_fact 和 skill_claim 类 memory 是哑火的**:上财、中南财大、CFA、Tushare 这 4 条记住了等于没记,面试 22 turn 一次都没"用上"。第二,**memory 之间会语义粘连**(turn 13 学生反过来纠正系统把中信建投面板和硕士 XGBoost 当成同一个 pipeline)—— 这是 production AI agent 里最忌讳的 failure 模式,因为它**显得产品没真在听**。

更尴尬的是,系统在 score.misses 里 8 次写"未联用招商基金经历",但它**自己的出题侧根本没给学生联用招商基金的入口**(唯一一次问招商基金 turn 7 还问错了方向 —— 学生 chat turn 4 都已经说过"我在固收+ 不是权益深度参与"了)。这是**系统的左手在批评右手** —— PM 视角看,这是评分 prompt 跟出题 prompt 没共享同一份 memory context 的典型症状。

所以,如果让我给学院老师一个直接的答案:**"系统懂学生"这件事在 JobRadar 里是真材实料,不是花架子,但目前的"懂"还停留在 evidence 类长文本(德方纳米 / XGBoost / 海天)这 3-4 条主线上,对 identity / skill / 学生主动暴露的 gray area 是没"用上"的**。建议在 ship 给 MF/MBA 同学前,**先修两个 bug**:(1) 让评分 prompt 跟出题 prompt 看同一份 memory(消除"左手批右手"); (2) 让 chat 里学生主动暴露的 gray area(如"我只写了 1500 字")在 memory 写入时打 `self_disclosed_gap` 标签,出题侧针对性 probing。修完之后这套系统就配得上"AI 行研面试教练"这个定位了 — 现在还差最后一公里。
