## 2. 叙事框架：5 个 AI 决策

整本 case study 围绕**5 个真实做过的 AI 决策**展开，每个决策一页，结构完全一致，让评审进入扫读节奏。

5 个决策：
1. **简历解析：单次 prompt 还是 ReAct Agent？** → ReAct loop + 4 个 tool
2. **模型选择：单一模型还是按任务匹配？** → 多模型策略（GLM-4.7 解析 + DeepSeek 重排）
3. **Top 5 推荐：纯 LLM 暴力搜，还是 4 层漏斗？** → 4 层漏斗（SQL → 规则 → 情报增强 → LLM 重排）
4. **AI 改写：套固定模板，还是按 JD 反向挑卖点？** → JD-driven 反向匹配 + 量化数字加强
5. **Agent trace：给不给用户看？** → 折叠默认隐藏 + 终端风格实时打印

**叙事锚点：求职 4 步闭环**
```
找岗位 → 改简历 → 准备面试 → 投递
✓ Top5  ✓ AI改写  ✓ 模拟面试  ⚙ 投递插件（开发中）
```

### 页 3-7 · 5 个判断（统一模板）

**模板**（每页都用同一套布局）：

```
判断 N · ●●○○○        ← 进度点
─────────
【决策标题】           ← Fraunces 28pt

─ 上下文 ─
[2-3 句话说清楚当时面对什么情况、为什么必须做这个决策]

─ 选项 ─
▢ 选项 A · 一句话描述              [+/-]
▢ 选项 B · 一句话描述              [+/-]
✓ 选项 C · 一句话描述              ← 选中

─ 我选 X · 因为 ─
[3-4 句推理，每句必有"判断"，不是"描述"]

─ 验证（数据 / 用户反馈）─
[1-2 句结果，配 1 个数字加粗]
```

**5 个判断的内容种子**：

#### 判断 1 · Agent ReAct loop（页 3）
- **标题**：简历解析：单次 prompt 还是多步 Agent？
- **上下文**：应届生简历格式杂乱（PDF / docx / 扫描件），需要做"读 → 抽结构 → 匹配公司库 → 推断目标"四件事，单次 prompt 全做完会幻觉/漏字段
- **选项**：A. 单次 long prompt（简单但易幻觉）／ B. 4 个独立 prompt 串联（缺上下文）／ **C. ReAct loop + 4 个 tool**
- **理由**：每一步失败都能定位、每一步耗时可单独优化、用户能看到 trace（连接到判断 5）
- **验证**：解析准确率 **87%**（字段无需用户纠正），4 步独立可调试

#### 判断 2 · 多模型策略（页 4）
- **标题**：不是"选一个最好模型"，而是"在不同环节匹配不同模型"
- **上下文**：中文场景 + 应届生用户对延迟敏感 + 内测预算有限。Anthropic / OpenAI 在国内调用慢且合规风险高
- **选项**：A. 全程 GPT-4 / Claude（贵 + 慢 + 中文不一定最好）／ B. 全程国产单模型（省心但有任务不擅长）／ **C. 按任务匹配模型**
- **理由**：简历解析 Agent 用 **GLM-4.7**（中文长文本理解强 + 国内延迟低）；Top 5 重排用 **DeepSeek**（推理能力强 + 性价比高）；两层都有规则兜底
- **验证**：解析 P50 **6.4s** / 推荐 P50 **3.8s** / 单用户成本 **¥0.12**

#### 判断 3 · 4 层漏斗（页 5）⭐ 含架构图
- **标题**：Top 5 推荐：纯 LLM 暴力搜，还是 4 层漏斗？
- **上下文**：岗位库万级，给每条都跑 LLM 不现实（成本/延迟）；但纯规则又太死板，捕捉不到语义匹配
- **选项**：A. 纯 LLM 全表（贵 + 慢）／ B. 纯规则 Top 5（快但僵）／ **C. 4 层漏斗：SQL 粗筛 → 规则细分 → 情报增强 → LLM 重排**
- **理由**：每层各干擅长的事 + 每层有 fallback；SQL 把万级压到 200，规则排出 Top 20，LLM 只对 5 条重排
- **架构图**（70% 页面占比）：4 个横向 box + fallback 箭头
  - Layer 0：SQL 粗筛（10000 → 200）
  - Layer 1：规则打分（5 个子分：objective / preference / base_job / company_priority / rule）
  - Layer 2：情报增强（snapshot boost）
  - Layer 3：LLM 重排（DeepSeek，5 条）
- **验证**：单用户成本 **¥0.12** vs 假设全 LLM 方案 **¥21.50**（**降到 1/180**）

#### 判断 4 · JD-driven 改写（页 6）
- **标题**：AI 改写：套固定模板，还是按 JD 反向挑用户的卖点？
- **上下文**：应届生简历"什么都想写"，但 HR 半秒看完只扫 JD 相关关键词。改写不能"通用美化"——必须按这个具体岗位去挑用户简历里最对得上的证据
- **选项**：A. 给 3 个固定方向（强量化/强因果/强影响）—— 太死板 ／ **B. JD-driven 反向匹配** ／ C. AI 自动改 → 失控
- **理由**：HR 决策窗口是"JD 关键词命中率"——AI 必须从 JD 反推回去挑证据，不能 generic。互联网岗位重数字 + 项目影响力；研究 / 战略岗位重方法论 + 推理路径；工程岗位重技术栈 + 系统设计。**因岗而异，不一刀切**
- **配图**：JD → 用户简历卖点反向匹配的流程图（左 JD 关键词 / 中连线 / 右用户简历段落）
- **验证**：JD-driven 卖点重组采纳率 **74%** / 量化加强 **68%** / 技术栈对齐 **71%** / 仅 **8%** 用了"自定义"slot

#### 判断 5 · Trace 折叠（页 7）
- **标题**：AI 黑盒还是开盒？给用户看推理过程的代价是什么
- **上下文**：LLM 推理过程对懂的人是"信任凭证"，对不懂的人是"信息过载"
- **选项**：A. 完全不显（被怀疑"AI 是不是瞎推"）／ B. 默认展开实时打印（小白蒙）／ **C. 折叠默认隐藏 + 终端风格实时打印**
- **理由**：终端风格视觉上跟"工程师在看 log"一样可信，不强迫普通用户去理解；展开率本身就是数据信号
- **验证**：trace 展开率 **8%**，但展开过的用户 D7 留存 **38%** vs 未展开 22%（高 **1.7 倍**）

### 页 8 · 数据验证

**目标**：用数据 + 用户原话给 5 个判断打分，**必有一个错判**。

**布局**：
1. 顶部：整体漏斗图
2. 中部：5 个判断的验证表（5 行 × 4 列：判断/我赌的/实际/评分）
3. 下部：用户原话 3 段
4. 底部：「我做错了什么」slot

**整体漏斗**（基于 300 用户 6 周数据）：

| 阶段 | 校招 (180) | 实习 (120) | 总 (300) |
|---|---:|---:|---:|
| 注册 | 180 (100%) | 120 (100%) | **300** |
| 上传简历 | 168 (93%) | 112 (93%) | **280 (93%)** |
| 解析成功 → Top 5 | 166 (99%) | 111 (99%) | **277 (99%)** |
| 进入工作台 | 159 (96%) | 106 (95%) | **265 (96%)** |
| 应用 ≥1 条 AI 改写 | 132 (83%) | 76 (72%) | **208 (78%)** |
| **回访自报有投递** | **38 (24%)** | **49 (46%)** | **87 (33%)** ⚠️ |

**关键反差**：
- 96% 进工作台 → 78% 应用改写 → **仅 33% 真去投** （中间掉 45pp）
- 校招改最多（83%）但投得最少（24%）；实习改最少（72%）但投得最多（46%）

**模拟面试数据**（验证投递信心瓶颈）：
| 指标 | 数值 |
|---|---:|
| 用过 mock interview 的用户 | 74 (28% of 工作台) |
| 完成至少 1 轮面试 | 47 (64%) |
| **用过 mock 的投递率** | **51%** |
| **没用 mock 的投递率** | **25%** |
| **差距** | **+26 pp** ⭐ |

**5 个判断验证表**：

| # | 判断 | 我赌的 | 实际 | 评分 |
|---|---|---|---|---|
| 1 | Agent ReAct loop | 解析准 + 可观测 | 87% 解析准确率，4 步独立可调试 | ✅ |
| 2 | 多模型策略 | 中文延迟低 | 6.4s 解析 / 3.8s 推荐 | ✅ |
| 3 | 4 层漏斗 | 成本可控 | ¥0.12 vs ¥21.50（1/180） | ✅✅ |
| 4 | JD-driven 改写 | 比固定模板准 | 74% 采纳率，仅 8% 用自定义 | ✅ |
| 5 | Trace 折叠 | 不打扰 + 增信任 | 展开率 8%，展开者留存 1.7× | ⚠️ 部分 |
| - | **整体** | 推荐 + 改写够用 | **真瓶颈在投递（33%）** | ⚠️ 错判 |

**用户原话 3 段**：

> "挺有用的。之前我在拉勾刷一直只看互联网，用了 JobRadar 才发现像华泰、中信这种券商也在招数据分析的实习。Top 5 里有 2 家是我之前完全不会去查的。"
> *— 数据分析实习用户 · 已投 4 家*

> "它根据岗位帮我重新调过一段实习经历，把我做过的 A/B 实验放到最前面，因为那家公司 JD 里就提了 A/B。我自己写简历的时候真没想过要按 JD 来调，挺受启发的。"
> *— 互联网产品方向校招用户 · 改了 6 版简历*

> "产品挺好的，但说实话这两个月我也还在准备阶段，简历改完了暂时没投。等春招大规模开始可能会回来用。"
> *— 量化方向校招用户 · 暂时没回来*

**「我做错了什么」slot**：

> 我以为 AI 解决的是"推荐准不准 + 改写好不好"。
>
> 数据显示前 4 步几乎全过（96% 进工作台、78% 应用改写），但只有 33% 真去投——中间掉了 45 个百分点。
>
> 更耐人寻味的是：校招用户改最多（83%）却投得最少（24%），实习用户改最少（72%）却投得最多（46%）。
>
> 回访发现校招学生卡在两个地方：怕被秒拒（信心问题）和不知道这家今年到底招几个（信息不对称）。改简历是低风险动作，按"投递"按钮才是高风险。
>
> 我们已经把模拟面试做出来了，数据显示用过的人投递率从 25% 提升到 51% —— 验证了"投递信心"确实是关键瓶颈。下一步要解决的是"按按钮"这个动作本身的成本——所以投递插件正在开发。
>
> AI 把"推荐 + 改写"做到 80 分容易，让用户真按下投递键才是产品下一阶段要解的题。下一版的北极星指标从"AI 推荐准确率"换成"投递转化率"。

### 页 9 · 反思 · AI 时代 PM 工作方式

**目标**：voice 页，让评审记住候选人。**不堆数据**，是观点陈词。

**布局**：
1. 「我从 JobRadar 学到的 3 件事」（3 段，每段 50-80 字）
2. 「我作为 AI PM 的工作方式」（3 个 bullet，30 秒读完）
3. 「下一步路线图」（5 行表格）
4. 联系方式（页脚一行）

**3 件事**：

> **1. AI 时代，PM 的判断比执行更值钱。**
> 4 层漏斗的架构判断是我做的，代码是 AI 写的。多模型策略的取舍是我做的，集成是 AI 写的。判断"什么值得做、为谁做、做到什么程度"是 PM 的护城河——这件事 AI 反而帮不上忙。
>
> **2. AI 不是答案，是放大镜。**
> 我以为 AI 推荐 + 改写就是产品的答案。结果 300 个用户的数据告诉我，真问题在投递信心。AI 让你 80 分容易做到，但同时把"用户真正卡在哪"暴露得无处可藏。PM 不能再靠"我以为"——必须正视数据反过来打脸的判断。
>
> **3. 速度 × 判断质量 = 新的 PM 方程式。**
> 6 周、300 用户、5 个 ship 出去的判断。不是因为我快，是因为 AI 把"试错成本"降到了零。PM 的工作变成：生成假设 → AI 快速 ship → 看数据 → 调整下一个假设。对错不再是问题，迭代速度才是。

**3 个工作方式 bullet**：

> • **判断 · 执行分离**：我定义问题、做取舍、判断 AI 输出好坏；AI 负责把判断变成代码、设计、文案。
>
> • **快循环**：1 周原型 → 1 周用户测试 → 改判断。不写 200 页 PRD，写 5 个判断 + ship 出去看反应。
>
> • **数据先于直觉**：每个判断都预设一个"如果错了我会看到什么"——准备好被打脸，比假装永远对值钱。

**路线图**：

| 时间 | 关键动作 | 预期 |
|---|---|---|
| **✓ 已上线** | 模拟面试（Voice + Device Check + AI Interviewer） | 缓解面试焦虑、增强投递信心 |
| **⚙ 进行中** | 网页投递插件（Chrome extension） | 一键把推荐岗位投出去 |
| **1–2 个月** | 招聘体量预估（爬历年公告 + LLM 推断"今年招几个"） | 解信息不对称 |
| **3–6 个月** | 校招专属"先投试错"模式 + 申请追踪 | 用低风险投递验证简历 |
| **目标** | **投递转化率 33% → 50%+** | 北极星指标 |

## 8. 成功标准

case study 算成功，必须做到：
- [ ] 评审 10 秒能记住封面 hook
- [ ] 5 个决策页节奏一致，可扫读
- [ ] 每个判断都有"我赌的 vs 实际"对照
- [ ] 至少 1 个诚实的"错判"slot
- [ ] 数据图表 1 张（漏斗 + 4 层架构）能让评审停留 30 秒
- [ ] 用户原话不像 marketing 文案，像真实学生说话
- [ ] 反思页有"我作为 AI PM"的明确观点
- [ ] PDF 在 Mac/Windows 打开都不变形（字体嵌入）

## 9. 不在范围内（YAGNI）

明确**不做**的事：
- ❌ 团队介绍 / 致谢
- ❌ 长篇产品文档 / spec sheet
- ❌ 工程实现深度细节（数据库 schema、部署架构）—— 评审是 PM 不是工程师
- ❌ 竞品对比表 —— 喧宾夺主
- ❌ 未来 12 个月以上的远期规划
- ❌ 多语言版本 —— 投国内大厂用中文
- ❌ 视频版 / 网页版 —— 单 PDF 足够
