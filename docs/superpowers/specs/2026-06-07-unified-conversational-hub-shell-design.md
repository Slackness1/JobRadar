## 本期范围三条拍板(2026-06-09)

1. **简历优化 = 接口位,归 `resume-copilot` 分支。** 原型虽把打分报告 + 雷达 + 逐段缺口 + A4 预览 + 全屏编辑器都画出来了,但**这一期我只建外壳 + 画布槽接口位**;打分报告/编辑器内部由 resume-copilot 分支照原型填进同一个槽。本期 chip 可点、点开是占位(或挂已有打分),不建内部视图。
2. **思考卡这期接"真数据浅层":** 「我的理解」(确认赛道 + 记忆)、4 个节点状态、召回/打分计数全接**真后端**;每步展开的工具 Input/Output 明细**先尽量填、不强求完整结构化 trace**,留下一期后端 trace 增强。
3. **后端"会话拆独立实体"延后。** spec §十一 点名的"会话外键指向简历"是唯一后端数据模型变更,**这一期不做**;先用现有单会话模型把前端外壳落地,多简历多会话血缘留下一期后端专项。

## 目标(一句话)

把现在分散在多个页面/分支的求职模块,收敛成**一个对话 Hub 外壳**:一条对话主轴贯穿始终,右侧一个"会变形的画布槽"按需展示不同模块的结构化视图,左侧一条可收起的导航栏 + 常驻身份。学生感受是"一个会切换专用视图的助手",而不是在几个产品之间跳来跳去。

## 为什么这么做(产品判断)

- **门槛要低、观感要轻** —— 对话 base 是已被验证的成熟形态(DeepHire),上手门槛低。
- **但不能变套壳** —— SAIF 明确对"DeepSeek 套壳"脱敏、要"可证伪反馈"。我们的护城河是结构化深度(梯队骨架 / 三维情报 / 记忆驱动精排)。纯聊天框会把深度藏起来,**正好长得最像套壳**。
- **结论** —— 留住对话 base 的低门槛,同时把结构化深度作为"激活的视图"亮出来。深度不是负担,是"懂这个学生、懂金融市场"的可见证据。

## 本期范围(已与用户确认:做"前者")

**做:** 立统一外壳 + 接进两个最成熟的模块(**职位推荐** / **梯队骨架**)。
**留接口位,不做内部:** 简历优化(在另一分支)、模拟面试(已存在,仅接"全屏跳转"入口)。
**后端:** 本期几乎不动(复用现有接口);唯一可能的小新增见"待规划项"。

## 一、外壳结构

```
┌──────────────┬─────────────────────────────────────────┐
│ 侧边栏(可收起)│            主壳(一套设计语言)              │
│              │                                          │
│ ✦ 新对话 ◀───┼─ 第一项 = 对话 Hub(默认落地;右槽空、对话居中)│
│ ▤ 职位推荐 ──┼─→ 右槽 = 推荐 feed     ┐ 三个"切视图"       │
│ ▦ 梯队骨架 ──┼─→ 右槽 = 档次全景       │ (不真跳页,槽变形)  │
│ ▧ 简历优化 ──┼─→ (接口位,本期禁用占位) ┘                  │
│ ◉ 模拟面试 ──┼─→ ★全屏接管(唯一真跳转,同会话同记忆)        │
│ 👤 个人档案 ─┼─→ B 档案:确认信息 + AI 推断待确认,可拍板/纠正 │
│ ⏱ 历史记录   │                                          │
│ ─────────    │                                          │
│ 🙂 身份常驻 ◀┼─ 底部头像+名字(轻量"它记得你",点开=完整档案)│
└──────────────┴─────────────────────────────────────────┘
```

三个区域职责:

1. **左:可收起侧边栏(新做)** —— 导航 + 历史 + 底部身份常驻。收起后只剩图标(极简/轻);展开是完整导航。当前代码无侧边栏(现为下拉/弹窗式),本期新建。
2. **中:对话主轴(复用)** —— 永远在,是整个产品的脊柱。复用现有 `RecommendChatPane` + `Composer` + 思考时间线(`ThinkingCard`/`TraceCard`/`MemoryToast`)。
3. **右:按需结构化面板(重构)** —— **默认不显示**,对话全宽。只有当一次技能跑完、学生**主动点结果卡上的「查看」**,结构化面板才滑出来(岗位匹配 / 梯队骨架 / 公司情报);可关掉回到全宽对话。**它是"跑完技能后主动点开的产出",不是"点模块就在的面板"。**

> **关键修正(2026-06-08,看真机原型后):** 早一版设想"点模块 → 右栏立刻铺结构化结果",实测**不够无感**——还是像跳进一个面板。改成 **DeepHire 式"对话内跑技能"**:点模块只在对话里触发一次执行(路径节点 + 思考时间线),完成后落一张**结果卡**,**点开才看**结构化视图。**所有模块统一,无一例外**(连简历优化、面试也走这条路径,只是点开后的视图是全编辑页/全屏间,见 §二)。推荐工作台现状的固定三栏(骨架 360 / 对话 1fr / feed 440)整体废弃。

## 二、激活语义(无感的核心 —— DeepHire 式"激活 → 说一句 → 跑技能")

**两步手感(2026-06-09 定稿,以原型 `hub-app.jsx` 为准):点模块 = 只"激活";打一句话 = 才"激发交付物"。**

- **第一步「激活」(arm):** 点 chip / 侧边栏 / 落地卡 → 该模块**高亮**(土红选中态),composer 上方浮一条引导 `已激活「职位推荐」· 说一句就开始 —— 例如「给我推荐一下岗位」`。**此刻什么都还没跑**,右槽不动。再点一次取消激活。
- **第二步「激发」(fire):** 学生**打一句话**(任意自然语言,不必照抄示例)→ 落学生发言 → **跑技能**:对话内出思考卡(见下)→ 跑完落**结果卡** → 学生**主动点结果卡 CTA** 才进入那个模块的视图。
- **也可不先点 chip,直接打字。** NL 意图路由(`fallback`)能从"看看券商资管的梯队 / 给简历打个分 / 推荐岗位"直接命中模块走同一条跑技能路径。

> 为什么两步:实测"点 chip 直接跑"还是像跳进一个面板。两步把"选模块"和"提需求"分开,让学生明确是**他说了一句话**才触发交付,主动权在他 —— 这才无感。

**例外:个人档案不是"跑技能"。** 它是学生自己的档案,点开**直接看**(确认/纠正闭环),不出思考卡、不落结果卡。原型 `runSkill('profile')` 直接 push 一句 AI 话 + 开面板。

进入手感统一(除档案),只有"点开后那个视图的形态"按模块不同:

| 模块 | 激活入口 | 点结果卡 CTA 后进入的视图形态 |
|---|---|---|
| 职位推荐 | chip / 侧边栏 / 落地卡 / NL | **侧面板**「岗位匹配」(宽 ~448,可关回全宽对话) |
| 梯队骨架 | 同上 | **侧面板**「梯队全景」(宽 ~436,复用 Confirm Profile 左栏 rail) |
| 简历优化 | 同上 | **侧面板**「打分报告」(宽 ~500)→ 其右上角「展开编辑器」才进**全屏编辑页**。**不跳过打分这步**(2026-06-09 用户明确)。本期此面板是接口位/占位,内部归 resume-copilot 分支 |
| 模拟面试 | 同上 | **全屏面试间**(跳 `/interview`,结束回 Hub,同会话同记忆) |
| 个人档案 | 侧边栏 / 底部头像 | **侧面板**「档案」**直接开**(不跑技能) |

**四模块思考路径节点(每步对应后端真做的一步,统一 4 字一步):**

| 模块 | 节点① | 节点② | 节点③ | 节点④ |
|---|---|---|---|---|
| 职位推荐 | 锁定赛道 | 检索岗位 | 三维打分 | 排出推荐 |
| 梯队骨架 | 拉取公司 | 梯队分档 | 背景定档 | 铺出全景 |
| 简历优化 | 解析简历 | 诚实打分 | 定位缺口 | 给出建议 |
| 模拟面试 | 调取记忆 | 匹配考官 | 备好题库 | 进入面试间 |

后端对应:职位推荐 = seed(确认赛道+L3)/ recall(sub_cat 召回)/ 规则三维分 / rank;梯队骨架 = load GT 公司 / 建梯队阶梯 / grounded 背景定档 / 组装+挂情报;简历优化 = parse / 8 维 rubric / 逐段 gap / 出报告;模拟面试 = load 记忆 / 匹配考官 rubric / 备题库 / 进面试间。(单岗「深挖」「深度优化」是 view 内的二级技能,做对应前端时再定。)

**思考显示 = 一张「深度思考卡」,两段式(2026-06-09 定稿,以原型 `hub-deepthink.jsx` 为准):**

节奏:`我的理解(spinner 起步)` → `思考过程(跑完自动折叠)` → `结果卡`。

> **删掉了 spec 早一版的"顶部轻量气泡"。** 用户明确"thinking bubble 多余,去掉,只留一个思考动效"。现在**「我的理解」自带 spinner 直接起步**,它本身就是等待期的轻量指示。**全程只有一个思考动效。** 不用 border-beam 环绕。

1. **「我的理解」(可见、不折叠 —— 护城河)** —— 顶部 `我的理解` 小标 + 一句话画像 `我理解你要的是 —— <真实在招的投研/券商资管岗,不是泛泛金融岗>`,下面一行 **赛道 pill + 记忆 pill**(记忆 pill 用**单色时钟图标**,不是彩色小标 —— 用户"彩色小标掉价、一律不要"),再下面一段 **typewriter 打字机推理**(`结合你确认过的赛道和偏好…我会先锁定范围,再检索…`)。取自**确认信息 + 统一记忆**,用**真记忆**撑(反套壳)。
2. **「思考过程」(跑完自动折叠,点开可看)** —— 跑时展开,展示 4 个节点的**链式时间线**(连接线 + 圆点状态 `✓`/`spinner`/`○` 单色 Lucide 图标);每个节点可展开看 **Input / Output + 工具名**(如 `lock_track` / `search_candidates` / `score_jobs`)+ 完成后的**结果 chips**。**跑完整卡自动折叠**成一行 `✓ 思考过程 · 4/4 · 已完成 ▾`,想看再点开。
   - 本期(2026-06-09 拍板):节点状态、`我的理解`、召回/打分计数接**真后端**;每步 Input/Output 明细**尽量填、不强求完整结构化 trace**,留下一期后端 trace 增强。

标准流(以职位推荐为例,其它三个同构):
```
点「职位推荐」(只激活,高亮 + "说一句就开始" 提示)
  → 打 "给我推荐一下岗位"(激发)
  → 深度思考卡:我的理解(赛道+记忆+打字机) → 思考过程 4 节点(锁定赛道→检索岗位→三维打分→排出推荐)→ 自动折叠
  → 落结果卡:"岗位匹配已就绪 · 按 投研·券商资管 评估 40 个、匹配 39 个 〔查看岗位〕"
  → 点〔查看岗位〕→ 右侧「岗位匹配」面板滑出
  → 关掉 → 回到全宽对话
```

"无感"靠三条:
1. **永不瞬移进面板。** 结构化面板只在技能跑完 + 学生点「查看」后出现,是产出不是落点。激活态(点 chip)绝不开面板。
2. **转场被"说"出来 + 路径可见。** 助手先出"我的理解",再跑 4 节点链,学生看着它"想",而不是被啪一下甩进一个列表。
3. **一套设计语言。** 外壳 + 所有面板统一赭红(HiFi)。推荐/骨架/HiFi/确认/面试**已是赭红**,唯一天蓝是简历 workspace(本期不并入),天然满足。

## 三、个人档案(B:确认/纠正闭环)

**逻辑沿用现有那套,只重做呈现层。** 现有底座:`ArchivePanel`("📌 我的档案")/ `ArchiveEntryCard` / `StudentKbDrawer`,后端 `account_memory` 8 类 + 确认/归档/删除接口(`confirmStudentExperience` / `archiveStudentExperience` / `deleteStudentExperience` / `listStudentExperiences` / `getStudentKbIndex`)。

数据分层(改之前必须懂):
- **确认信息** = 学生在确认页拍板的(目标赛道 confirmed_sub_cats、城市、求职阶段/毕业时间、实习/全职)—— 权威、展示在档案。
- **统一记忆(account_memory)** = 系统跨对话/解析积累的 8 类(经历/证据/技能主张/偏好/身份事实/目标/承诺/**弱点信号**)—— 引擎,绝大部分不露脸。**弱点信号绝不直接展示给学生。**

B 闭环(可见的护城河):
- AI 从对话推断出一条 → 浮到档案里标成"AI 推断 · 待确认"(= 现有 `confirmed=false` 的条目)。
- 学生**确认** → 升格为确认信息(现有 `confirmStudentExperience`),推荐随之变。
- 学生**纠正/否掉** → 记忆被纠正,不再拿错画像喂下去(本期 v1 = 现有 archive/拒绝;行内编辑值见"待规划项")。

呈现层重做目标:好看、好读、像产品(替换现有"不好看"的记忆面板外观),把"确认信息"与"AI 推断待确认"两类视觉分层,确认/纠正动作一眼可点。底部头像是它的轻量常驻入口。

## 四、对话 Hub 落地态

- 默认落地 = Hub:对话居中、**全宽**(像 DeepHire 主页),无右侧面板,底部 composer 带 skill chip。
- 可选快捷入口卡(职位推荐 / 简历优化)作为对话之外的第二入口。
- 学生说话或点 chip → **对话内跑技能 → 结果卡 → 点「查看」才滑出结构化面板**(见 §二),不是一点就铺。

**chip 集合(2026-06-07 用户拍板,与 resume-copilot 分支对齐):**
- 三个**模块 chip**:`职位推荐` / `梯队骨架` / `简历优化`。三个都**可点、走两步激活**(原型即如此);区别只在点结果卡后:推荐/骨架进真视图,**简历优化进接口位占位**(内部归 resume-copilot 分支)。不再"灰置"。
- `深度搜索` **不是模块**,是**职位推荐内部的开关(开/关)**——控制是否走深度匹配(rerank+narrative),不在 Hub 顶部单列成 chip。
- (曾有"只做 深度搜索+简历优化 两 chip"的另一版理解,已废,以本条为准。)

## 六、数据流(壳内)

- **单会话**:整个外壳共享一个 sessionId(现有 `?session=N` 机制),Hub / 推荐 / 骨架 / 档案 / 面试 全程同一会话。
- **单记忆**:对话写入 → `account_memory`(L3)→ 喂推荐精排 + 档案展示;档案的确认/纠正回写记忆,形成闭环。

## 十一、数据模型:账号 / 简历 / 会话 / 记忆 四层(2026-06-08 拍板)

```
账号 (user_key) ──── 记忆 L3 / account_memory   ← 永远锚账号层,跨简历跨会话
   └─ 简历/画像 A（默认;多数 SAIF 学生只有这份;confirmed_sub_cats/城市/毕业/解析经历）
         ├─ 会话①「固收方向」(working_query + 对话 + feed 状态)
         ├─ 会话②「研究岗」
         └─ 会话③「战略」
   └─ 简历 B（英文版/转行版,少数人才有）
         └─ 会话…
```

四层职责:
- **账号(user_key)= 记忆锚点。** 统一记忆 `account_memory`(L3)挂这里,跨简历、跨会话持久——"它记得你"的根。**本层现状已正确(account_memory 本就是 user_key),不动。**
- **简历/画像 = 中间层。** 喂推荐/骨架的起点(confirmed_sub_cats 等)。
- **会话(历史记录)= 最下层,嵌在简历下。** 一条探索线程 = 一次对话 + 当时 working_query/feed。**用户拍板"会话嵌简历下"**:简历切换低频,以简历为单位 fan-out 会话最自然、血缘最干净。

UI 行为(保证单简历不乱):
- 侧边栏「历史记录」= **当前简历名下的会话列表**(主视图)。
- **简历切换器**只在 >1 份简历时显形(历史记录顶部小选择器);单简历学生看不到这层。切简历 → 历史记录整列换成那份简历的会话。
- 「新对话」= 在当前简历下开新会话,起始 working_query 由该简历 confirmed_sub_cats 播种(沿用现成 `seed_working_query`)。
- 任何会话都拉**同一份账号级记忆**,简历切换不打断记忆。

**唯一需要的后端模型拆分:** 现状 `session` 把"简历/画像 + 会话 + working_query"揉成一团 → 一份简历开多方向会被迫造多份简历。要把**"会话"拆成独立实体,外键指向"简历/画像"**;记忆留账号层不动。这是本期 Hub 改造唯一的后端数据模型变更。
