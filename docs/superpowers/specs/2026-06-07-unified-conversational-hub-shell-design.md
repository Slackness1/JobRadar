# 统一对话 Hub 外壳 — 设计文档

> 日期:2026-06-07 · 会话:网站设计-devvpstmux(orchestrator) · 状态:待用户 review
> 参考形态:DeepHire(对话 base + 点 skill 在原地激活模块 + 显式思考过程)

## 目标(一句话)

把现在分散在多个页面/分支的求职模块,收敛成**一个对话 Hub 外壳**:一条对话主轴贯穿始终,右侧一个"会变形的画布槽"按需展示不同模块的结构化视图,左侧一条可收起的导航栏 + 常驻身份。学生感受是"一个会切换专用视图的助手",而不是在几个产品之间跳来跳去。

## 为什么这么做(产品判断)

- **门槛要低、观感要轻** —— 对话 base 是已被验证的成熟形态(DeepHire),上手门槛低。
- **但不能变套壳** —— SAIF 明确对"DeepSeek 套壳"脱敏、要"可证伪反馈"。我们的护城河是结构化深度(梯队骨架 / 三维情报 / 记忆驱动精排)。纯聊天框会把深度藏起来,**正好长得最像套壳**。
- **结论** —— 留住对话 base 的低门槛,同时把结构化深度作为"激活的视图"亮出来。深度不是负担,是"懂这个学生、懂金融市场"的可见证据。

## 本期范围(已与用户确认:做"前者")

**做:** 立统一外壳 + 接进两个最成熟的模块(**职位推荐** / **梯队骨架**)。
**留接口位,不做内部:** 简历优化(在另一分支)、模拟面试(已存在,仅接"全屏跳转"入口)。
**后端:** 本期几乎不动(复用现有接口);唯一可能的小新增见"待规划项"。

## 一、外壳结构

```
┌──────────────┬─────────────────────────────────────────┐
│ 侧边栏(可收起)│            主壳(一套设计语言)              │
│              │                                          │
│ ✦ 新对话 ◀───┼─ 第一项 = 对话 Hub(默认落地;右槽空、对话居中)│
│ ▤ 职位推荐 ──┼─→ 右槽 = 推荐 feed     ┐ 三个"切视图"       │
│ ▦ 梯队骨架 ──┼─→ 右槽 = 档次全景       │ (不真跳页,槽变形)  │
│ ▧ 简历优化 ──┼─→ (接口位,本期禁用占位) ┘                  │
│ ◉ 模拟面试 ──┼─→ ★全屏接管(唯一真跳转,同会话同记忆)        │
│ 👤 个人档案 ─┼─→ B 档案:确认信息 + AI 推断待确认,可拍板/纠正 │
│ ⏱ 历史记录   │                                          │
│ ─────────    │                                          │
│ 🙂 身份常驻 ◀┼─ 底部头像+名字(轻量"它记得你",点开=完整档案)│
└──────────────┴─────────────────────────────────────────┘
```

三个区域职责:

1. **左:可收起侧边栏(新做)** —— 导航 + 历史 + 底部身份常驻。收起后只剩图标(极简/轻);展开是完整导航。当前代码无侧边栏(现为下拉/弹窗式),本期新建。
2. **中:对话主轴(复用)** —— 永远在,是整个产品的脊柱。复用现有 `RecommendChatPane` + `Composer` + 思考时间线(`ThinkingCard`/`TraceCard`/`MemoryToast`)。
3. **右:会变形的画布槽(重构)** —— 一个槽,按激活的模块换内容:推荐 feed / 梯队骨架 / (简历占位)。Hub 默认态下槽为空,对话居中。

> **关键变化:** 推荐工作台现状是**固定三栏**(骨架 360 / 对话 1fr / feed 440)。本期改为**两栏 + 画布槽**:骨架从"常驻左栏"降为"画布槽能显示的一种视图",对话升为主轴,左栏让位给导航侧边栏。

## 二、激活语义(不突兀的核心)

两类激活,手感不同,必须区分清楚:

| 模块 | 激活方式 | 行为 | 跳转? |
|---|---|---|---|
| 职位推荐 / 梯队骨架 / 简历优化 | 对话里的 skill chip **或** 侧边栏点选 | **右槽在同一个壳里变形**,对话不掉 | 否(壳内切视图) |
| 模拟面试 | 侧边栏点选 | **全屏接管**,结束回 Hub | 是(唯一真跳转) |

"不突兀"靠三条铁律保证:

1. **壳内切视图绝不真跳页。** URL 可变(便于分享/刷新),视觉上是同一个壳,右槽滑入/变形。
2. **转场被"说"出来。** 助手先在对话里说"我来帮你看职位推荐…",思考时间线开始跑(已有),右槽随对话长出来;激活的 chip/侧边栏项高亮,学生始终知道自己在哪个模式。
3. **一套设计语言。** 外壳 + 所有壳内视图统一用赭红(HiFi)色系。现状:推荐/骨架/HiFi/确认/面试**已是赭红**,唯一的天蓝是简历 workspace(本期不并入,留接口位),所以本期天然满足。

## 三、个人档案(B:确认/纠正闭环)

**逻辑沿用现有那套,只重做呈现层。** 现有底座:`ArchivePanel`("📌 我的档案")/ `ArchiveEntryCard` / `StudentKbDrawer`,后端 `account_memory` 8 类 + 确认/归档/删除接口(`confirmStudentExperience` / `archiveStudentExperience` / `deleteStudentExperience` / `listStudentExperiences` / `getStudentKbIndex`)。

数据分层(改之前必须懂):
- **确认信息** = 学生在确认页拍板的(目标赛道 confirmed_sub_cats、城市、求职阶段/毕业时间、实习/全职)—— 权威、展示在档案。
- **统一记忆(account_memory)** = 系统跨对话/解析积累的 8 类(经历/证据/技能主张/偏好/身份事实/目标/承诺/**弱点信号**)—— 引擎,绝大部分不露脸。**弱点信号绝不直接展示给学生。**

B 闭环(可见的护城河):
- AI 从对话推断出一条 → 浮到档案里标成"AI 推断 · 待确认"(= 现有 `confirmed=false` 的条目)。
- 学生**确认** → 升格为确认信息(现有 `confirmStudentExperience`),推荐随之变。
- 学生**纠正/否掉** → 记忆被纠正,不再拿错画像喂下去(本期 v1 = 现有 archive/拒绝;行内编辑值见"待规划项")。

呈现层重做目标:好看、好读、像产品(替换现有"不好看"的记忆面板外观),把"确认信息"与"AI 推断待确认"两类视觉分层,确认/纠正动作一眼可点。底部头像是它的轻量常驻入口。

## 四、对话 Hub 落地态

- 默认落地 = Hub:对话居中(像 DeepHire 主页),右槽空,底部 composer 带 skill chip。
- 可选快捷入口卡(职位推荐 / 简历优化)作为对话之外的第二入口。
- 学生说话或点 chip → 对应模块在右槽长出来,对话继续。

**chip 集合(2026-06-07 用户拍板,与 resume-copilot 分支对齐):**
- 三个**模块 chip**:`职位推荐` / `梯队骨架` / `简历优化`(简历优化本期前端等 HiFi,先**灰置占位**,可见不可用)。
- `深度搜索` **不是模块**,是**职位推荐内部的开关(开/关)**——控制是否走深度匹配(rerank+narrative),不在 Hub 顶部单列成 chip。
- (曾有"只做 深度搜索+简历优化 两 chip"的另一版理解,已废,以本条为准。)

## 六、数据流(壳内)

- **单会话**:整个外壳共享一个 sessionId(现有 `?session=N` 机制),Hub / 推荐 / 骨架 / 档案 / 面试 全程同一会话。
- **单记忆**:对话写入 → `account_memory`(L3)→ 喂推荐精排 + 档案展示;档案的确认/纠正回写记忆,形成闭环。
- **画布槽状态**:外壳持有"当前激活模块"状态(none/推荐/骨架/简历),侧边栏与 chip 都改这一个状态;右槽据此渲染对应视图。推荐与骨架共享 workingQuery + skeletonReloadKey(现有 shell 已有这些共享态,迁移即可)。

## 七、明确不做(YAGNI / 留后续)

- 简历优化模块**内部**(另一分支)——本期只留侧边栏占位 + 约定接口位(画布槽里日后塞它的视图)。
- 模拟面试**内部**(已存在)——本期只接"全屏跳转入口 + 结束回 Hub"。
- 简历 workspace(天蓝)的设计系统收敛 —— 本期不并入,不动它。
- 档案行内编辑"改值"(v1 用现有拒绝/归档代替;见待规划项)。
- 后端新功能 —— 本期不引入(除非待规划项确认需要)。

## 八、待规划项(写实现计划时定)

1. **档案"纠正"是否需要新后端接口**:现有只有确认/归档/删除,没有"改值"。v1 决定:纠正 = 否掉错误推断(现有 archive),完整行内改值留 phase 2。若 review 认为 v1 必须能改值,则需加一个小的 edit endpoint —— 规划阶段拍。
2. **画布槽 URL 策略**:壳内切视图是否反映到 URL(`?view=skeleton`)以支持分享/刷新落回同一视图。倾向:是,但用浅 URL 不触发整壳重载。
3. **侧边栏收起态的持久化**(localStorage 记住用户偏好)。

## 九、简历优化接口契约(来自 resume-copilot 分支 handoff,2026-06-07)

简历优化在 Hub 是"接口位/占位",开发归 `resume-copilot` 分支。挂进画布槽的契约:

- **入口路由**:`/resume-copilot/editor`(三栏编辑页,未建)/ 本期可先挂已建的 `/resume-copilot/score`(打分报告)。
- **画布槽需传的状态**:`sessionId`(resume_copilot session)+ `X-Resume-User-Key`(owner 守卫用)。Hub 切到"简历优化"时把当前 session 传进去即可。
- **已可调后端 API**(都带 owner + `_assert_not_demo` 守卫):
  - `POST /api/resume-copilot/sessions/{id}/score` → 打分报告(8 维 + 现状/潜力区间 + 逐段缺口)
  - `POST /api/resume-copilot/sessions/{id}/deep-optimize/start` → 播种深度优化(入参 `{section,label,gaps[],detail,target_track}`)
  - 反问续走 `POST .../plan/turn`;改写写回走 `.../chat/apply-rewrite`
- **模块内部哲学**(不干预,记录):诚实打分 + 反问取证(绝不 AI 编内容刷分);深度优化一次只聚焦一段经历 + 锁定目标赛道(subcat);打分 8 维(6 通用 + 2 金融),「面试可防守性」已改名「佐证充分度」。
- **后端 backlog(已排,归 resume-copilot 分支)**:知识库接进深度优化——加 `PURPOSE_RESUME_OPTIMIZE`,**先接 podcast(金融招聘洞察现成对口)**,track-rubric 金融赛道薄、后补。

## 十一、验收(产品可见)

1. 从 Hub 开始,点"职位推荐"→ 右槽在原地长出推荐 feed,对话不掉、思考时间线在跑、chip 高亮 —— 无"跳到另一个产品"的割裂感。
2. 点"梯队骨架"→ 同一个槽换成档次全景;两个视图共享同一查询/会话。
3. 点"模拟面试"→ 全屏进面试,结束回到 Hub,记忆延续。
4. 个人档案:能看到"确认信息"与"AI 推断待确认"两层,能一键确认/否掉,确认后推荐跟着变;外观是重做过的、像产品的。
5. 整个外壳一套赭红设计语言,侧边栏可收起,收起后观感轻量。
6. 端到端:`npm run lint` + `npm run build` 必过。
