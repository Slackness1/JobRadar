## 一句话结论

**S1 把召回质量拉高 2.6 倍(nDCG 0.238→0.620),配对差 95% 置信区间 [+0.285, +0.477] 整段为正——统计上铁证。
但精准度仍有代价(跑偏率 19.6% > 8% 阈值),所以裁决:暂不翻开关。** 关键是:扩样本后看清了
**收益和风险各自集中在哪**,收口方向因此非常明确。

## 全体对照表(带 95% 置信区间)

|---|---|---|---|

## 扩样本逼出的三个关键事实(24 条看不到)

**事实 1 —— 现状对互联网学生几乎是瞎的,S1 在这里是干净的压倒性胜利。**

| 分段 | 腿 | Recall@20 | nDCG@10 | 跑偏率 |
|---|---|---|---|---|
| **互联网** (24q) | baseline | **9.1%** | **0.065** | 0.0% |
| | dense | 61.1% | 0.772 | **6.2%** |
| | hybrid | 56.7% | 0.763 | 11.2% |
| **金融** (48q) | baseline | 32.8% | 0.324 | 0.0% |
| | dense | 56.5% | 0.576 | 23.4% |
| | hybrid | 54.9% | 0.548 | 23.8% |

现状对互联网 nDCG 只有 **0.065**(sub_cat 闸 + track 映射偏金融,互联网工程/算法岗几乎召不到)。
dense 在互联网上 nDCG 0.772、**跑偏率仅 6.2%(已低于 8% 阈值!)**。池子 66% 是互联网,这块过去完全是盲区。

**事实 2 —— 跑偏 19.6% 几乎全来自金融,不是互联网。** 金融段跑偏 23.8%,互联网段才 11.2%(dense 6.2%)。
原因:金融语义近邻多(基金里的"销售/运营/中后台"和投研意思近但职能错),且金融 baseline 已覆盖易召的,
边际新增的更容易擦边。**收口该针对金融段下药。**

**事实 3 —— 纯 dense ≥ hybrid,sparse 是净拖累。** dense(0.641 / 58.1% / 跑偏17.7%)各项都略优于
hybrid(0.620 / 55.5% / 19.6%);sparse 单腿最弱还带最高跑偏(26.1%)。**RRF 融合关键词没加成,反添跑偏。
下一版应直接走纯 dense,sparse 顶多当 tie-breaker。**

## 逐条印证的模式(72 条)

- **空/弱 enrich 段全线大涨**:互联网 I1-I4 全部 ↑(baseline 多为 0.00 → 0.6~1.0);金融 P4 银行 / P7 金科 /
  P8 大宗(现状几乎 0)全部 ↑。这些是学生现在完全看不见的岗。
- **回退集中在"已 enrich 得好"的金融桶**:P3 私募基本面 7 条全 ↓(0.8~0.96 → 0.04~0.48),P2 卖方部分 ↓。
  baseline 在这些桶本就召得准,语义召回把擦边岗混进来稀释了排序。

→ **收口主策略「补位不替换」由数据强支持**:sub_cat 标得满的桶(私募/卖方)信 baseline;标得稀/空的段
(互联网/银行/大宗/金科)用 dense 补。这一招同时:① 杀掉 P3 这类回退 ② 砍掉金融段大部分跑偏 ③ 保住互联网的大胜。

## 收口路线(#314,逐步重测到三阈值全过)

1. **走纯 dense,弃 sparse**(数据显示 sparse 净拖累)。
2. **加相关性下限**:dense cosine 低于阈值的尾部候选直接砍(削金融段擦边跑偏)。
3. **补位不替换**:baseline 够数就用 baseline,不够才 dense 补——修 P3 回退 + 降金融跑偏。
4. 每步重跑 `32_run_eval.py`,跑偏 ≤8% + nDCG +15% + Recall 不降三条全过再翻 flag。
