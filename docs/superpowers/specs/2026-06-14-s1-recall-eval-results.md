# S1 召回离线 Eval — 结果报告

> 日期 2026-06-14 · 分支 hub-shell-frontend · 24 条 query(8 真实 SAIF persona × 3 意图)
> 判官:OpenCode deepseek-v4-flash(mimo 跨厂商 key 当日失效,先顶上;对 DashScope 向量召回引擎仍属跨厂商、无自评回路)。绝对校准待人工抽检。

## 一句话结论

**S1 把召回质量大幅拉高(nDCG ×1.78、Recall +22 个点),但精准度有真实代价(跑偏率 25.6% vs 现状 0%)——
正是"放开 sub_cat 闸会不会污染、丢学生信任"的量化版。eval 把这个风险抓到了,所以裁决:暂不翻开关,
先做精准度收口,再重测。**

## 对照表

| 召回腿 | Recall@20 | nDCG@10 | MRR | 跑偏率 |
|---|---|---|---|---|
| baseline(现状:sub_cat 闸) | 34.5% | 0.307 | 0.509 | **0.0%** |
| dense(仅语义向量) | **57.2%** | **0.556** | 0.833 | 26.5% |
| sparse(仅关键词 BM25) | 43.8% | 0.479 | 0.653 | 30.0% |
| **hybrid(S1)** | 56.6% | 0.549 | **0.860** | 25.6% |

裁决(spec 三阈值):
- ✓ nDCG@10 提升 ≥15%:hybrid 0.549 vs baseline 0.307(**×1.78**)
- ✓ Recall@20 不降:56.6% vs 34.5%
- ✗ 跑偏率 ≤8%:**25.6%** —— 卡在这条

→ **三缺一,留 OFF。** flag 默认就是 OFF,线上零影响。

## 三个关键发现(都很诚实)

**1. 真正的解锁是语义向量,不是混合。** dense 单腿(57.2% / 0.556)≈ hybrid(56.6% / 0.549),
sparse 单腿最弱(43.8%)。对中文 JD,语义向量挑大梁,BM25 经 RRF 融合几乎没加成、还带进点跑偏。
→ #313 标题问的"证明 hybrid > dense-only":**没证明,两者基本打平**。下一版应把权重压向 dense,
sparse 只当 tie-breaker,甚至先用纯 dense。

**2. 现状对"enrich 得好的赛道"已经很强,混合反而稀释。** 6 条回退里集中在 P3 私募基本面
(baseline 0.83~0.96 → hybrid 0.35~0.52)——这些 sub_cat 标得满、baseline 本就召得准,放开闸把
擦边岗混进来拉低了排序。**推论:混合不该"替换"baseline,应"补位"**——sub_cat 标得足够多就信
baseline,标得稀/空才用语义召回补。这同时修复 P3 这类回退。

**3. 语义召回对"体系没有桶/标得稀"的赛道是压倒性胜利。** P8 大宗能源(体系无此 sub_cat):
0.00→0.72 / 0.00→0.87 / 0.01→0.58;P1 医药基本面 0.00→0.64;P4 银行综合 0.03→0.74。
这些是现状彻底召不到、学生完全看不见的岗,语义召回直接救活。**18/24 条 query 上升,平均涨幅显著。**

## 跑偏 25.6% 是什么 / 怎么收口

跑偏 = hybrid top-20 里判官打 0 分(完全不对口)、且 baseline 也召不到的"新引进垃圾",每 20 个约 5 个。
多在 top-20 的尾部(语义相似但职能/行业错)。收口路线(逐个做完重测,目标把 25% 压到 ≤8%):

1. **相关性下限**:dense cosine / sparse BM25 低于阈值的候选直接砍,削掉尾部垃圾(最直接)。
2. **压向 dense + sparse 只做 tie-breaker**:或干脆纯 dense,先看纯 dense 加下限能不能达标。
3. **混合改"补位"不"替换"**:baseline 够数就用 baseline,不够才用语义补(同时修 P3 回退)。
4. 每动一步重跑 `32_run_eval.py` 看跑偏率/nDCG,直到三阈值全过再翻 flag。
