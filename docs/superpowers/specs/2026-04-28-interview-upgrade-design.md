# Mock Interview Upgrade — Design Spec

**Date**: 2026-04-28
**Owner**: chuanbo
**Status**: Draft → for review

## Goal

Turn the current "single LLM stream + TTS" mock interview into a **diagnostic interview** that gives the user actionable feedback per turn and a structured post-interview report. Specifically deliver four upgrades together in one launch:

1. **Per-question scoring** — after each user answer, score it against a rubric derived from the chip's nowcoder summary; show a brief reference answer ("如果是面霸会怎么答").
2. **Adaptive question selection** — first 5–6 turns from a fixed skeleton, last 4–6 turns generated by LLM as drill-downs targeting the user's weakest dimensions so far.
3. **Voice soft-scoring** — from the existing ASR transcript: filler-word rate, words-per-minute, pause count, response latency, plus an LLM-derived confidence score.
4. **Weekly practice plan** — a single markdown paragraph at the bottom of the report.

UI delivery model:
- **Live during interview**: only a 1-line "📌 我注意到你没提到 X" hint, fade-out 4s, non-blocking.
- **Final report page** (new): full per-turn breakdown, voice metrics aggregate, weekly plan.

## Non-goals

- Comparing scores across multiple sessions of the same chip (audit trail exists in DB, UI deferred).
- Calendar-style 7-day plan / multi-session re-engagement loop (could come later, this iteration ships A-tier weekly plan only).
- Real acoustic features for confidence (no audio waveform analysis post-ASR; confidence is text + timing based).
- Frontend test infra for the new components (lint + build is the verification floor).

## Architecture

### Data model

One new table, one extension. No destructive changes.

```
interview_turns                          ← NEW
─────────────────────────────────────────
id                INTEGER PK
session_id        TEXT INDEX            ← UUID from frontend (same as URL sessionId)
user_key          TEXT INDEX            ← X-Resume-User-Key, used for owner check
turn_index        INTEGER               ← 0-based
target_job        TEXT                  ← redundant, avoids per-turn lookup
question          TEXT
user_answer       TEXT                  ← transcript or text input
asr_transcript    TEXT                  ← full ASR with timestamps as JSON
                                         empty for text-mode users
voice_metrics     TEXT                  ← JSON: {filler_rate, wpm, pause_count,
                                                 response_latency_ms, confidence_score}
                                         all fields nullable
score_json        TEXT                  ← JSON: {overall: 0-100, hits: [..],
                                                 misses: [..], bonuses: [..]}
                                         null until async scoring completes
reference_answer  TEXT                  ← LLM-generated 3-5 sentence model answer
question_source   TEXT                  ← 'skeleton' | 'follow_up' | 'fallback'
created_at        DATETIME

interview_reports                        ← EXTEND
─────────────────────────────────────────
... existing fields ...
weakness_profile_json  TEXT             ← NEW
weekly_plan_md         TEXT             ← NEW
turn_count             INTEGER          ← NEW
```

**Why no separate `interview_sessions` table**: session_id is just a grouping key on `interview_turns`. Weakness profile is recomputed on-the-fly per turn (≤ 12 rows lookup, cheap).

`schema_patch.py` will gain: `CREATE TABLE IF NOT EXISTS interview_turns (...)` and idempotent `ALTER TABLE interview_reports ADD COLUMN ...` for the three new columns. Same pattern as the nowcoder tables.

### Service layer

```
backend/app/services/interview/
├── llm.py                  ← MODIFIED — orchestrator
├── scoring.py              ← NEW — rubric scoring (LLM)
├── reference_answer.py     ← NEW — generate model answer paragraph (LLM)
├── voice_metrics.py        ← NEW — pure-Python ASR transcript analysis
├── adaptive.py             ← NEW — skeleton queue + follow-up picker
├── weakness_profile.py     ← NEW — aggregate scores → weakness fields
├── report.py               ← MODIFIED — pull from interview_turns + weekly plan
└── prompts/                ← NEW — cache-friendly system prompts as files
    ├── scoring_system.md
    ├── reference_system.md
    └── follow_up_system.md
```

Each module has one job:

- **`scoring.py:score_answer(target_job, question, user_answer, chip_summary) -> ScoreResult`**
  v4-flash + JSON mode. Rubric derived from chip_summary's "what's tested" section.
  Returns `{overall, hits, misses, bonuses}`. Q5 hardening: malformed → `ScoreResult.empty()`.

- **`reference_answer.py:generate_reference(target_job, question, chip_summary, candidate_summary) -> str`**
  v4-flash. 3-5 sentences. Prompt explicitly forbids fabricating numbers / projects.
  Failure returns empty string; UI hides the section.

- **`voice_metrics.py:compute_voice_metrics(asr_transcript: dict) -> VoiceMetrics`**
  Pure Python: dictionary match for filler words, char-count / audio-duration → wpm,
  segment gaps > 1.5s → pause_count, AI-end → first user segment → response_latency_ms.
  Confidence subcall `score_confidence_from_transcript()` invokes v4-flash with transcript
  + cadence features; failure → null.

- **`adaptive.py:pick_next_question(session_id, target_job, chip_summary, weakness, db) -> NextQuestion`**
  Holds `SKELETON_QUESTIONS: dict[chip, list[str]]` (5-6 must-ask per chip).
  Turns 0-5: pop from skeleton, mark `question_source='skeleton'`.
  Turns 6+: v4-flash generates follow-up using "asked questions + weakness profile".
  LLM failure → next skeleton item, then generic fallback.

- **`weakness_profile.py:compute_weakness(session_id, db) -> WeaknessProfile`**
  Aggregate score_json across turns: top-N high-frequency miss tags, average score per
  dimension, gap warnings. Output: `{avg_score, weak_topics, strong_topics, gap_warnings}`.

- **`llm.py:process_turn(session_id, target_job, prev_answer, asr_transcript, db) -> StreamHandle`**
  Orchestrator. Per turn:
  1. Sync write `user_answer + asr_transcript` to current turn row.
  2. Fire-and-forget 3 parallel tasks (scoring / reference / voice metrics) via `ThreadPoolExecutor` — same pattern as `quick_enrichment.py`. Each task opens its own `SessionLocal` and updates the same turn row when done. (Existing `/turn` endpoint is sync; ThreadPoolExecutor avoids forcing a sync→async migration of the SSE generator.)
  3. Sync `compute_weakness()` + `pick_next_question()` → next question text.
  4. Sync insert next turn row (just `question`), stream question text via SSE.
  5. (No push notification — frontend polls `/turns/latest-score` at 1.5s for ready hints. MVP simpler than redis pubsub.)

All prompts live as `.md` files in `prompts/`. They're read once at module load and used as the system message verbatim — byte-stable for DeepSeek prompt cache hits.

### API surface

Three new endpoints, one modified endpoint.

```
POST   /api/interview/turn                    ← MODIFIED
       SSE response, new event types:
         data: {"type":"chunk", "delta":"..."}
         data: {"type":"turn_complete", "turn_index":3, "question":"..."}
       Old behavior preserved for non-type-aware clients (chunks still readable as text).

GET    /api/interview/sessions/{sid}/turns/latest-score   ← NEW
       Frontend polls 1.5s. Returns latest turn whose score_json just transitioned
       from null → set, plus a 1-line hint extracted from score.misses.
       Response: {turn_index: 3, hint: "📌 你这次没提到具体数字"} | null

GET    /api/interview/sessions/{sid}/turns                ← NEW
       Report page bulk fetch.
       Response: [{turn_index, question, user_answer, score, reference_answer, voice_metrics}, ...]
       Owner check: X-Resume-User-Key matches turn.user_key, else 403.

POST   /api/interview/report                  ← MODIFIED
       Reads from interview_turns, computes weakness_profile, generates weekly_plan_md
       via one final LLM call. Persists to interview_reports.
```

**Auth on new endpoints**: `interview_turns.user_key` is set on row insert from `X-Resume-User-Key`. GET endpoints reject mismatched key with 403. `POST /turn` keeps current stateless behavior — auth retrofit is out of scope (would require frontend/backend coordination separate from this work).

### Frontend changes

Two pages: existing `app/interview/[sessionId]/page.tsx` (interview live) and a new `app/interview/[sessionId]/report/page.tsx` (post-interview report). Reports were embedded at the bottom of the live page; now they get their own route.

**Interview live page** (`page.tsx`):
- New `<LiveHintBar/>` component — absolute-positioned 1-line bar below caption. `useLatestScorePolling(sessionId)` hits the new endpoint every 1.5s. Hint shows for 4s, fades out. Suppressed during Border Beam (avoid visual collision).
- New `useInterviewSSE()` hook replaces raw text SSE parsing. Dispatches by `type` field: `chunk` → caption character reveal (preserving current TTS-progress sync), `turn_complete` → switch UI to "awaiting answer" state, advance left progress rail.
- New `useTurnState(sessionId)` — local accumulator of `Turn[]` objects (question + user_answer pairs). Used to build the messages payload sent to `/turn`.

**Report page** (new):
1. **Overview card** — large overall_score number, 4 small bars for per-dimension scores (沟通 / 内容 / 自信 / 业务理解), short LLM summary line.
2. **Per-turn replay** — collapsible list. Each turn expands to show: question + user answer text, **score card** (overall + green✓ hits / red✗ misses / gold★ bonuses), **reference answer paragraph** ("📖 如果是面霸会怎么答"), tiny voice_metrics chips ("语速 240 字/分 · 填充词 3.2%/分钟").
3. **Voice performance card** — 4 averages (filler_rate / wpm / pause_count / confidence) plus an "ideal range" comparison bar.
4. **Weekly plan** — render `weekly_plan_md` as markdown.

Theme: stays inside `[data-theme="interview"]` scope, reuses existing terracotta + Fraunces tokens. New components import `interview-theme.css`.

### Error handling

Core principle: any single failure (scoring / reference / voice / adaptive) MUST NOT block the main flow (user keeps answering). Failed fields land in DB as null; frontend gracefully degrades.

| Failure point | Behavior | User impact |
|---|---|---|
| Scoring LLM fails / malformed JSON | turn.score_json stays null, no live hint | That turn has no live hint; report shows "评分服务暂不可用" placeholder |
| Reference LLM fails | turn.reference_answer stays null | Report hides "📖 面霸答" section for that turn |
| Voice metrics calc fails (no ASR / duration 0) | All voice fields null | Report hides voice card; text-mode users naturally take this path |
| Confidence subcall fails | confidence_score null only | Confidence bar shows "—", other dimensions normal |
| Adaptive LLM fails | Falls back to next skeleton question, then generic "请深入讲讲你最近的项目" | Invisible to user |
| Weakness compute exception | Returns empty profile, adaptive degrades to skeleton order | Invisible to user |
| Weekly plan LLM fails | weekly_plan_md = "本次面试反馈已生成，建议针对上述薄弱点逐个练习。" | Report still has content, just generic |
| `/turn` SSE stream drops | Frontend `useInterviewSSE` catches onerror → "网络中断，点击重试" | User retries |
| `interview_turns` table missing on startup | `ensure_compatible_schema()` auto-CREATEs it | Invisible |

All LLM calls go through Q5 hardening: try / except (ValidationError, JSONDecodeError, Exception) → logger.warning + fallback. Never raises 500.

Background tasks (ThreadPoolExecutor) use independent `SessionLocal` instances; failure of one does not affect the others.

### Testing

**Unit tests** (bulk of the suite — pure functions are easiest to verify):
- `test_voice_metrics.py` — given mock ASR transcript, verify filler_rate / wpm / pause_count are computed correctly.
- `test_scoring_prompt_builder.py` — verify rubric prompt contains chip_summary keyword sections, format byte-stable (cache-friendly).
- `test_adaptive_picker.py` — first 5 turns return skeleton in order, turn 6+ invokes LLM, LLM failure falls back to generic.
- `test_weakness_profile.py` — given a set of score_json rows, verify aggregate weak_topics ranking is correct.
- `test_scoring_handles_malformed_llm_output.py` — LLM returning non-dict / non-JSON string / missing fields → ScoreResult.empty().
- `test_reference_answer_handles_failure.py` — same pattern.

**Integration tests** (mock LLM client, run full turn flow):
- `test_turn_full_flow.py` — POST /turn → verify SSE emits `chunk` + `turn_complete` events, turn row written, 3 background tasks fired.
- `test_turn_score_polling.py` — after turn completes, GET /turns/latest-score returns latest scored turn.
- `test_report_aggregation.py` — given 10 turn rows, POST /report aggregates an InterviewReport with weakness_profile + weekly_plan populated.
- `test_owner_check_on_turns_get.py` — different user_key on GET /turns returns 403.

**E2E fake interview**:
- `test_e2e_fake_interview.py` — mock entire LLM stack, run 12 turns of "question → answer → score → next question", verify final report contains per-turn scores + references + voice metrics + weekly plan paragraph.

**Frontend**:
- No vitest infra in resume-copilot-web. Verification floor is `npm run lint` + `npm run build`.
- Manual test checklist at the end of this spec.

## Cost estimate

Per session: 4 LLM calls per turn × ~12 turns + 1 weekly plan call ≈ 49 calls.
With deepseek-v4-flash (~¥0.0001/1k prompt + ¥0.0008/1k completion) at ~2k prompt + 500 completion per call:
- Per session ≈ ¥0.05 (¥0.07 worst case with v4-pro on confidence subcall).
- 1000 sessions/day ≈ ¥50–70/day.

Prompt cache amortizes the static system prompts (chip summary often shared within a session).

## Manual test checklist (post-deploy)

- [ ] Start interview as logged-in user → 12 turns runs to completion
- [ ] Live hint appears within ~2-3s of submitting first answer
- [ ] Border Beam suppresses live hint while AI is speaking
- [ ] Submit voice mode answer → voice_metrics fields populated in report
- [ ] Submit text mode answer → voice card hidden in report
- [ ] Force scoring LLM 500 (block deepseek temporarily) → live hint silent, report shows placeholder, interview continues
- [ ] Cross-user GET /turns returns 403
- [ ] Report page weekly_plan section renders markdown correctly
- [ ] Per-turn replay expands/collapses smoothly
- [ ] Demo session route still works (no breakage to existing flows)
