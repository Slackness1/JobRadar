# S1 召回离线 Eval Set — 设计 spec

> 目的:给"混合召回(S1)到底比现状好不好"装一把**可量化、可复现的尺子**。

> 权重怎么调、跑没跑偏,全部用指标说话。这套 eval set 同时是日后 S2(学习排序)的训练/验证地基。

## 一句话要回答的问题

> 对一个真实学生 persona,**混合召回**(语义 dense + 关键词 sparse + 丢掉 sub_cat 闸)
> 召回出来的前 20 个岗,**相关性是不是显著高于现状**(纯 SQL + sub_cat 闸)?
> 以及——它会不会把**不该出现的岗**(跑偏)也捞上来?

这两问对应两类指标:**召回质量**(越高越好)和 **跑偏率**(越低越好)。后者是你最担心的
"放开 sub_cat 闸会不会污染、丢学生信任"的量化版。

---

## 三条召回腿要同台比

为了证明"混合 > 现状",一次 eval 要同时跑四套召回,在同一批 persona 上比:

| 代号 | 召回方式 | 代表 |
|---|---|---|
| **A. baseline** | 现状:纯 SQL + sub_cat 闸 + 质量闸 | 线上现在跑的 |
| **B. dense-only** | 只语义向量(丢 sub_cat 闸) | 验证"语义召回单独够不够" |
| **C. sparse-only** | 只 FTS5 关键词(丢 sub_cat 闸) | 验证"关键词单独够不够" |
| **D. hybrid (S1)** | dense + sparse RRF 融合(丢 sub_cat 闸) | 我们要上的 |

候选池 = 四套各取 top-20 的**并集**去重(典型 40~60 个/persona),逐个打标签。
这样四套的指标都能从同一份标签算出来,公平。

## ⭐ 岔路 1:persona 用哪批人?

| 选项 | 内容 | 利弊 |
|---|---|---|
| **(a) 真实 SAIF 8 persona + 2 真学生**(推荐) | 复用 `00_personas-saif/` 那 8 个 + 钦奕阳/张志杰 | 真实、贴试点、含弱背景压测样本;但只有 10 个,统计噪声大 |
| (b) 真实 10 个 + LLM 扩 40 个合成 | 拿真 persona 当种子让模型造 40 个 | 样本量够;但合成 persona 自带模型偏好——这正是我们否决"LLM 温启动"时担心的循环,**会污染 eval** |
| (c) 纯 50 个合成 | 全 LLM 造 | 量大但最不可信 |

**我的推荐:(a)。** 宁可 10 个真的,不要 50 个掺了模型口味的——eval set 一旦掺假,
后面所有"涨分"都不可信。10 个不够就**每 persona 多设几个意图查询**(同一个人问
"量化研究""固收交易""想去买方"算三条),把样本量做到 30~40 条 query 级,而不是注水 persona。

## ⭐ 岔路 2:相关性标签谁来打?(最关键)

每个 (persona, 候选岗) 打 **0~3 分**:3=高度相关该排最前 / 2=相关 / 1=擦边 / 0=不相关或跑偏。

| 选项 | 谁打 | 利弊 |
|---|---|---|
| **(a) 跨厂商 LLM judge**(推荐做初版) | 用 eval harness 那个 `mimo-*` 判官(故意非 deepseek,防自评) | 快、可复现、几百条几分钟;但判官自己也可能"偏宽",需校准 |
| (b) 你的 Pro 日卡 | deepseek-v4-pro 高 effort 打 | 质量高;但日卡今日时效,且和库里 deepseek 基线同源有自评嫌疑 |
| (c) 人工(你/老师) | 肉眼 | 最准、是金标准;但 30 query × 50 候选 = 1500 条,人工吃不消 |

**我的推荐:(a) 跑全量初版,(c) 抽样校准。** 让跨厂商判官打全部 1500 条,
再由你/老师**人工抽 50~80 条**复核判官打得准不准(算判官 vs 人工的一致率)。
判官一致率够高 → 信它的全量分;不够 → 收紧判官 prompt 重打。这样既有规模又有金标准锚点。
> 这一步和你说的"以强模型 review 会不会有失偏颇"是同一个担忧——所以**判官必须被人工抽检校准**,
> 不能裸用。

## ⭐ 岔路 3:"跑偏"怎么定义、阈值定多少才放行?

跑偏 = D(hybrid)召回进 top-20、但被判官打 **0 分**(不相关)、**且** baseline 不会召回的岗。
即"放开 sub_cat 闸新引进来的垃圾"。

**off-target rate = (hybrid top-20 里 0 分且 baseline 召不到的岗数) / 20**,对所有 query 取平均。

放行阈值建议(待你定):
- 召回质量:**hybrid 的 nDCG@10 ≥ baseline × 1.15**(至少好 15%)且 **Recall@20 不降**
- 跑偏护栏:**off-target rate ≤ 8%**(20 个里最多 1.6 个新垃圾)

两个都满足才翻 flag;否则留 OFF,回去调 RRF 权重 / 加相关性下限。

---

## 指标(四套召回各算一份)

- **Recall@20** — 所有 ≥2 分的相关岗,有多少落进 top-20(召回全不全)
- **nDCG@10** — top-10 排序质量,高分岗排越前越好(排得好不好)
- **MRR** — 第一个相关岗的排名倒数(首屏体验)
- **off-target rate**(上面定义)— 跑偏护栏

输出一张 4×4 表(召回腿 × 指标)+ 每个 persona 的 top-5 对照(肉眼能扫)。
